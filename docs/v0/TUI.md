# TUI 设计文档

## 1. 概述

TUI 是 CLI 的可视化封装。用户输入 `st` （无子命令）后进入全屏 TUI 界面。

框架：Textual（Python）

依赖文件：`requirements-tui.txt`

核心原则：
- TUI 调用与 CLI 相同的 service 层，不引入新的业务逻辑。
- 在窗口宽度足够时渲染选中股票的自绘日 K 图，窄屏时自动隐藏图表。
- K 线图保持透明底色，不使用会遮住终端背景的色块。
- 支持修改操作，不是只读。


## 2. 全局布局

```
┌─────────────────────────────────────────────────────────────────┐
│  [提示栏] Tab:切换页面 ↑↓:选择 Enter:操作 q:退出              │
├─────────────────────────────────────────────────────────────────┤
│  [关注池]    [持仓]    [扫描]                    ← Tab 页签    │
├──────────────────┬────────────────────────┬────────────────────┤
│                  │                        │                    │
│     左侧列表      │        右侧详情         │   K线图 + 成交量    │
│                  │                        │                    │
│                  │                        │      日 K 图        │
│                  │                        │                    │
│                  │                        │                    │
├──────────────────┴────────────────────────┴────────────────────┤
│  [状态栏] 数据日期: 2026-06-05 | 持仓: 3 | 关注: 7             │
└─────────────────────────────────────────────────────────────────┘
```

- 全屏单页切换，三个 Tab 页面。
- 每个页面统一左列表 + 右详情的基础结构。
- 当窗口宽度达到宽屏阈值时，在详情右侧显示独立第三栏 K 线图。
- 窄屏时隐藏 K 线图，右侧详情占据剩余空间。
- 顶部提示栏显示当前可用的快捷键。
- 底部状态栏显示数据概况。

### 2.1 K 线图规范

- 图表数据来自本地 `daily_kline`，仅展示日 K。
- 图表按当前可用宽度尽量显示更多历史 K 线。
- 价格区显示 OHLC K 线：
  - 红色表示上涨，绿色表示下跌，白色表示平盘。
  - 使用终端字符自绘影线和实体，不引入 plotext/textual-plotext。
- 成交量是图表的固定组成部分，显示在价格区下方的独立子图中。
- 不叠加均线；TUI 字符格无法像 GUI 一样做像素级控制，图表优先保证 K 线和成交量清晰。
- 图表标题显示股票代码、名称、最新收盘价和涨跌幅。
- 图表底部显示日期范围和成交量最大值。
- 图表、详情栏、容器都必须保持透明背景，以保留 ghostty 等终端的背景质感。


## 3. 页面设计

### 3.1 关注池（Tab 1）

左侧列表列：
| 列 | 说明 |
|----|------|
| 名称 | 股票名称 |
| 明天买 | buy_tomorrow 字段。如果为True，文字显示黄色 |

右侧详情（选中某只股票后展示）：
- 基本信息：代码、名称、扫到的形态、加入日期
- 备注：note 字段完整内容
- AI 买入分析：最近3条 type=watch 的 ai_logs 记录（如果少于三条就全列出来）
  - 结论（conclusion）
  - 分析内容（content）
  - 分析日期
- 宽屏第三栏：展示该股票日 K 和成交量

操作快捷键(需要显示在提示栏)：
| 键 | 操作 | 对应 CLI |
|----|------|----------|
| a | 添加股票到关注池（弹出输入框） | `st record add <code>` |
| d | 从关注池移除当前选中 | `st record rm <code>` |
| g | 标记"明天买" | `st record go <code>` |
| n | 编辑备注（弹出输入框） | `st record note <code>` |
| w | 对选中股票执行买入分析 | `st watch <code>` |
| Enter | 从关注池转入持仓（弹出买入价输入） | `st hold in <code> --price <p>` |

### 3.2 当前持仓（Tab 2）

左侧列表列：
| 列 | 说明 |
|----|------|
| 名称 | 股票名称 |

右侧详情（选中某只股票后展示）：
- 持仓信息：代码、名称、买入价、买入日期、止损价、目标价
- 备注：note 字段完整内容
- AI 卖出分析：最近一条 type=alert 的 ai_logs 记录
  - 结论（conclusion）
  - 分析内容（content）
  - 分析日期
  - 建议止损/目标价（如有）
- 宽屏第三栏：展示该股票日 K 和成交量

操作快捷键：
| 键 | 操作 | 对应 CLI |
|----|------|----------|
| s | 设置止损价（弹出输入框） | `st hold set <code> --stop <p>` |
| t | 设置目标价（弹出输入框） | `st hold set <code> --target <p>` |
| n | 编辑备注（弹出输入框） | `st hold set <code> --note <msg>` |
| x | 平仓（弹出卖出价输入） | `st hold out <code> --price <p>` |
| r | 减仓（弹出卖出价输入） | `st hold out <code> --price <p> --dec` |
| A | 对选中股票执行卖出分析 | `st alert <code>` |
| Shift+A | 对全部持仓执行卖出分析 | `st alert` |
| h | 查看历史交易记录（弹出浮层） | `st hold history` |

### 3.3 全市场扫描（Tab 3）

左侧为扫描器选择 + 结果列表：

扫描器选择区：
- 三个扫描器按钮/选项：box / channel / ma_alignment
- 用户选中后按 Enter 或 空格 触发扫描

结果列表列：
| 列 | 说明 |
|----|------|
| 代码 | 股票代码 |
| 名称 | 股票名称 |
| 形态 | 当前扫描器名称 |
| 关键指标 | ScanResult.indicators 中的核心数值 |

右侧详情（选中某只扫描结果后展示）：
- 股票基本信息：代码、名称
- 形态判定指标：indicators 字典中的全部键值对
- 是否已在关注池中
- 宽屏第三栏：展示该股票日 K 和成交量

操作快捷键：
| 键 | 操作 | 对应 CLI |
|----|------|----------|
| Enter | 将选中股票加入关注池 | `st record add <code>` |
| 空格 | 执行/切换扫描器 | `st find <scanner>` |
| c | 导出当前结果为 CSV（弹出路径输入） | `st find <scanner> --csv <path>` |


## 4. 交互规范

### 4.1 导航
- `Tab` / `Shift+Tab`：切换页面标签
- `↑` / `↓`：在左侧列表中移动选择
- `←` / `→`：在同一页面的左右栏之间移动焦点（如详情区有可滚动内容）
- `q`：退出 TUI

### 4.2 输入弹窗
修改操作统一弹出 Modal 输入框：
- 标题显示当前操作（如"设置止损价 - 000001"）
- 输入完成后 Enter 确认，Esc 取消
- 输入验证失败时在弹窗内提示错误，不关闭弹窗

### 4.3 异步操作
- AI 分析（watch/alert）耗时较长，执行时右侧详情区显示"分析中..."加载状态
- 全市场扫描耗时较长，执行时列表区显示进度提示
- 异步操作不阻塞 UI 导航

### 4.4 刷新
- 修改操作完成后自动刷新当前页面数据
- 不提供手动全局刷新，数据变更即时反映


## 5. 入口

```
st        → 进入 TUI（无子命令时）
st tui    → 进入 TUI（显式子命令，别名）
st <cmd>  → 执行 CLI 命令（有子命令时走原有 CLI）
```

`main.py` 中判断：如果没有传入子命令，启动 TUI App；如果传入子命令，走原有 argparse 分发。


## 6. 架构约束

- TUI 代码放在 `stocktools/tui/` 目录下。
- TUI 只调用 service 层，不直接访问 repo 或 provider。
- TUI 不依赖 `stocktools/output/`（TUI 有自己的渲染）。
- TUI 不依赖 `stocktools/cli/`（二者平级，共享 service 层）。

```
CLI 层 ─┐
         ├──→ Service 层 → Domain / Data
TUI 层 ─┘
```

目录结构：
```
stocktools/tui/
├── __init__.py
├── app.py              # Textual App 主类，Tab 切换逻辑
├── screens/
│   ├── __init__.py
│   ├── watchlist.py    # 关注池页面
│   ├── holdings.py     # 持仓页面
│   └── scan.py         # 扫描页面
├── widgets/
│   ├── __init__.py
│   ├── stock_list.py   # 左侧列表通用组件
│   ├── detail_panel.py # 右侧详情通用组件
│   └── input_modal.py  # 输入弹窗
└── styles/
    └── app.tcss        # Textual CSS 样式
```


## 7. 样式方向

- 配色：终端默认色为主，关键状态用颜色区分
  - 正常股票名称显示：白色
  - 明天买标记：橙色
  - 止损价触及：红色
  - AI 结论 buy：红色 / sell：绿色 / hold：黄色 / wait：灰色
- 不使用 emoji，用文字和颜色传达状态
- 列表紧凑排列，详情区留足阅读空间
